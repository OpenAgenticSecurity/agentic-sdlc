# 五维生产就绪实现审计清单（Production Readiness Audit）

**状态**: accepted baseline
**更新日期**: 2026-11-21
**English**: [production-readiness-audit.md](production-readiness-audit.md)
**配套 Skill**: [`skills/audit-production-readiness/SKILL.md`](../skills/audit-production-readiness/SKILL.md)

> **为什么需要这份清单**：单次 PR 审查能拦下局部漏洞，但一个累计过百个绿灯 PR 的仓库在生产上仍可能是 Demo 级——例如消费守卫读的字段线上永远没人写、代码/模板/部署三层默认值漂移、超时与连接池上限互相冲突，或 `STATUS.md` 标了完成却未接通线上入口。本清单将实战沉淀的整仓实现审计方法论抽象为可复现、语言无关的审计纪律。

---

## 1. 审计参数与诚实协议

开工前必须填完全部参数（填不出来的写 `UNKNOWN`，不许留空）：
- **审计目标与精确基线**：目标仓库 + `git fetch --prune origin` 后的精确 40 位 `origin/<default>` 提交号。
- **部署假设**：架构拓扑、副本数、租户模型（单客户私有化 vs 多租户 SaaS）、有状态存储类型。
- **运行时访问权限**：`none` 或严格只读（`SELECT`、不带 `ANALYZE` 的 `EXPLAIN`、只读指标/日志/集群查询）。
- **上一轮基线**：上一轮 `EVIDENCE.md` 路径（或写 `首轮`）以及明确的范围外项。

不可违反的红线：
- [ ] **假设存在问题**：禁止无 `file:line` 或实测证据的正面表扬。
- [ ] **每条结论标注来源**：`[Fact]`（代码直读 `file:line`）、`[Measured]`（实测命令与输出）、`[Inference]`（完整推理链）或 `[Unknown]`。
- [ ] **附置信度与证伪条件**：标明 `高 / 中 / 低` 置信度，并写明一句话“什么证据会推翻该结论”。
- [ ] **全程只读、绝不落密钥值**：审计期间绝不修改或提交仓库；涉及密钥仅记录键名、数量与文件权限位。

## 2. 七条证据纪律（防止“假审计”）

- [ ] **1. 否定性结论追到构造点**：绝不因为 `grep` 没搜到就断言“缺少超时/鉴权/上限/调用方”——必须沿调用方 → 对象构造 → 依赖注入/中间件/配置一路追查。
- [ ] **2. 核验数据活性**：任何守卫、配额或看板指标读取了字段 `F`，必须找到它在**生产路径上的写入方**（`file:line`）。只有测试写或主路径恒为 0 的守卫等于死防线。
- [ ] **3. 宣称能力从线上入口追查**：对 `STATUS.md` 打勾项或已关闭 Issue，从真实 HTTP/CLI/Worker 入口追到实现；仅覆盖非线上路径的记为“失实宣称”。
- [ ] **4. 计数可复算且分母一致**：每个数字和比例都附未经截断的精确命令与范围（混用 `git ls-files` 与 `find` 会悄无声息污染分母）。
- [ ] **5. 性能结论必须有实测**：无 `[Measured]` 数据时一律标为 `[Unverified Hypothesis]`，并附最小实测或压测方法。
- [ ] **6. 默认值必须分三层查**：逐层核对（a）代码/Settings 默认值、（b）随附部署模板（`.env.example`/Helm/Compose/IaC）、（c）线上实际生效值（不可见时标 `[Deployment-Dependent]`）。改了部署模板不证明存量环境已生效。
- [ ] **7. 数值推导写全算式并核对语义**：把不等式完整写出，并在 `file:line` 确认每项语义是单次调用、单次执行内共享还是跨轮累计。

---

## 3. 耦合、修复与部署纪律

- [ ] **上限类问题先画关系再定数值**：涉及超时、重试、并发、连接池、队列可见性或预算配额时，列出同一资源上的全部相邻上限并由不等式推导数值——禁止拍脑袋给孤立常量。
- [ ] **修复建议必须写前提与失效边界**：写明修复在什么条件下会失效（如“改非 root”在挂载 token 文件为 `0644` 或 `/proc/1/environ` 同 uid 可读时无效），并估算改动半径（文件数、迁移、契约）。
- [ ] **标注部署依赖严重度**：依赖集群/代理/存储配置的条目一律标 `[Deployment-Dependent]`，并给最小只读探针（`结果 A -> 严重度 X；结果 B -> 严重度 Y`）。
- [ ] **主审复核子代理结论**：子代理产出的全部高危 `[Fact]`、否定性结论与统计数字必须由主审复核；未复核项标 `[Unverified Subagent Inference]`，失败或被拦维度标 `NOT_EVALUATED`。

---

## 4. 对抗性双假设裁决（先辩后裁）

打分前，用证据分别为两个对立假设写最强辩护：
- **H1（生产级）**：在声明的部署假设下，当前架构可支撑生产规模与持续演进。
- **H2（Demo 级）**：流量增长或需求变化将迫使结构性推倒重来。

基于已核验证据给出清晰裁决（`<= 200` 字），禁止和稀泥。

## 5. 五大跨语言审计维度

### A. 架构（Architecture）
- [ ] **分层与循环依赖**：UI / API / 领域层 / Worker / 持久化职责清晰；业务逻辑未泄漏进传输层。
- [ ] **可替换性**：更换数据库、消息队列、外部依赖或 LLM 供应商的预估改动文件数。
- [ ] **数据流与活性**：端到端请求链路闭合，无无主状态、无只读不写的假字段。
- [ ] **状态归属与恢复**：会话和长任务状态存放在哪；进程重启、发版与节点失效时能否恢复。
- [ ] **水平扩展障碍**：内存态、Sticky Session、单 Worker 锁、不可迁移的本地磁盘存储。

### B. 设计（Design）
- [ ] **API 与错误契约**：统一的错误模型、版本策略，严格区分内部异常与用户可见信息。
- [ ] **抽象与重复密度**：给出精确复算命令的重复代码密度；识别过度工程与欠工程。
- [ ] **类型纪律**：严格静态类型（`strict: true`、mypy、Rust/Go/Java 领域类型）而非无类型字典/`any` 裸传。
- [ ] **配置卫生**：12-Factor 环境分离、密钥与配置解耦，相互耦合的上限配置具备启动期校验。

### C. 功能（Functionality）
- [ ] **功能现实对照表**：宣称能力 × 状态（`完整` / `部分` / `桩` / `缺失` / `失实宣称`）× 线上入口 `file:line`。
- [ ] **Vibe Coding 残留**：硬编码 mock、死代码、注释代码块、仅被测试调用的生产函数。
- [ ] **边界条件与幂等**：空态、并发竞争、重试、写入/支付类操作幂等性、取消与中断恢复。
- [ ] **测试真实性**：断言真实行为还是只测“不报错”；核心路径测试覆盖比。

### D. 性能（无实测一律标 `[Unverified Hypothesis]`）
- [ ] **延迟构成**：关键路径耗时拆解、外部/工具调用串行还是并行、流式响应处理。
- [ ] **前端性能**：Bundle 体积预算、无谓重渲染、长列表虚拟化、流式 Markdown/宽表扩展性。
- [ ] **后端性能**：N+1 查询、异步事件循环中的同步阻塞 I/O、连接池总账（`sum(进程数 * (pool + overflow)) * 发布倍率 <= 0.7 * max_connections`）、缓存策略。
- [ ] **成本与并发瓶颈**：Token/费用计量活性（如含 AI 能力）以及目标并发下的首个瓶颈推演与实测方法。

### E. 安全（Security）
- [ ] **凭证与运行期暴露**：硬编码密钥数量（附扫描命令），客户端/服务端/日志/环境变量/挂载文件/`/proc` 密钥边界。
- [ ] **鉴权覆盖率**：用路由/依赖图计算 `M / N` 端点鉴权覆盖率（禁止仅靠简单 grep 装饰器）+ 租户/对象级 IDOR 核查。
- [ ] **注入与危险 Sink**：SQL/NoSQL、Shell 命令、XSS/HTML、模板注入、SSRF、路径穿越、不安全反序列化。
- [ ] **AI/Agent 特有攻击面（如适用）**：Prompt Injection 暴露面、工具最小权限身份、破坏性操作人工确认门（HITL）、多维循环/费用上限、跨租户记忆隔离、反审批疲劳“15 秒决策卡”（监控无脑秒批橡皮图章率）、三角制衡指标（效率 × Reopen/改判率 × Canary 客观真值），以及**自学习权限不对称**（自动沉淀的规则只能收紧约束或补上下文，绝不能自动放宽权限、取消审批或写入永久白名单）。
- [ ] **发版前运维防炸红线**：核实 `SECRET_KEY` / 签名密钥在发版前后保持一致（变更会同时破坏密码哈希、登录态与库内加密字段）；上线前必须完成可验证数据库备份、向前兼容的非破坏性迁移与核心表行数对账；容器镜像锁定不可变 Digest（禁 `:latest`）并开启 `read_only`、`no-new-privileges` 与 `cap_drop: ALL`。

## 6. 交付物清单与跨轮可比性

- [ ] **审计报告（`REPORT.md`）**：部署假设与基线、H1/H2 裁决、五维评分卡（`1–5` 分或 `NOT_EVALUATED`）、按严重度排序的问题清单、功能现实对照表、可复算量化指标表、探针清单、待拍板决策、与上一轮对比（`Closed`/`Persisting`/`New`）、未覆盖范围（`does_not_prove`）与**自我质疑**（本审计最可能错的三处及证伪检查）。
- [ ] **证据锚点（`EVIDENCE.md`）**：范围、精确提交号、最短复核命令、已知缺口与下一轮承接项——绝不把完整仓库副本冻结进审计目录。
