# 后端 Vibe Coding 性能排雷清单（8 类实证陷阱）

**状态**: accepted baseline
**更新日期**: 2026-11-20
**English**: [backend-performance-review.md](backend-performance-review.md)
**实证来源**: [《Vibe Coding 应用性能：能跑和扛得住》](https://fz.cool/vibe-coding-backend-performance/)（~38 万行 FastAPI + SQLAlchemy + Celery + K8s 后端 100+ 项真实性能优化；主动发现仅 16%，CI 发现仅 5%）

> **残酷现实**：前端出错会给你一个看起来正常的假页面；后端变慢会给你一个永远停在 `running` 的任务——在 Agent 平台里，后台循环和慢任务烧的还是真金白银的 Token 费用。Agent 验收的世界是 **P50**（6 个事件、38 条资产、23 秒跑完）；真实线上炸在 **P99 尾部**（上千事件、十万资产、90+ 分钟长任务）以及任何单个 diff 都看不见的**跨层乘积**上。

## 1. 八类实证性能陷阱审查清单

### 1. 启动、容器与发布生命周期

- [ ] **依赖与项目本体必须在构建期装完**：运行时禁止 `uv run` 联网安装（否则单次容器启动被拖慢到 5 分钟，直接干掉健康检查；改为直接 `exec` venv 内可执行文件后降至约 8 秒）。
- [ ] **正确的 PID 1 信号转发**：用 `exec` 让服务进程成为 1 号进程（或使用 `tini`），确保 `SIGTERM` 干净送达。
- [ ] **三种 K8s 探针各管各的**：`startupProbe` 兜慢启动；`livenessProbe` 只做轻量存活检查（如心跳文件，禁止用耗时 9 秒+ 的 `celery inspect ping` 或查 DB）；`readinessProbe` 管流量准入。
- [ ] **关停链不等式**：`terminationGracePeriodSeconds ≥ preStop + 最长任务 + 余量`（默认 30 秒会在每次发布时直接 `SIGKILL` 长任务 worker）。
- [ ] **压缩按响应类型分开**：SSE/流式响应必须绕过缓冲式 GZip 中间件，避免首块被憋住长达十余秒，同时保留对大 JSON 接口的压缩。

### 2. 数据库、索引与连接池总账

- [ ] **列表接口统一分页与索引**：复用统一分页依赖（如默认 20、上限 200）、服务端搜索过滤、以及匹配查询的复合索引 `(tenant_id, ...)`；**外键列必须显式建索引**（PostgreSQL 不会自动建）。
- [ ] **在 ORM 与测试层堵死 N+1**：关联默认 `lazy="raise"` 或显式 `selectinload`/批量 `IN`；对热接口增加 **SQL 查询预算回归测试**（通过 `before_cursor_execute` 统计单请求 SQL 次数）。
- [ ] **写时预聚合**：看板统计（如 Token 用量）在写入时记录，只做 `SUM`，禁止每次请求把全量正文拉进 Python 计算。
- [ ] **连接池总账写进合同测试**：核对 `Σ(进程数 × (pool_size + max_overflow)) × 滚动发布倍数 ≤ 0.7 × max_connections`（进程增多时前置 PgBouncer）。
- [ ] **坏连接异常路径先 `rollback()`**：长任务持有的连接断开后，异常处理必须先回滚再写失败态（否则执行永远卡在 `running`）；子进程绝不继承父进程数据库连接。
- [ ] **时长与计数默认 64 位**：`duration_ms`、计数器和自增 ID 一律 `BIGINT`（32 位毫秒约 24.86 天即溢出）。

### 3. 事件循环与并发

- [ ] **按实际 I/O 驱动选 `def` 或 `async def`**：函数内有同步 SQLAlchemy `Session`、同步 Redis 或同步文件解析就用 `def`（交由线程池）；只有整条链路全异步（`asyncpg`/`AsyncSession`）或显式 `asyncio.to_thread` 卸载阻塞调用时才用 `async def`。
- [ ] **绝不带着数据库连接去 `await` 远程/LLM 调用**：远程等待前提交并归还短 Session，返回后确需写库再开新短事务。
- [ ] **线程池与连接池预算对齐**（Starlette/AnyIO 默认线程池 40），给连接池设置取连接超时，耗尽返回 `503`。
- [ ] **把规则写成 Lint**：开启 Ruff `ASYNC` 规则，并用 AST 检查在 CI 禁止 `async def` 路由注入同步 `Session`。
- [ ] **锁与事务测试必须跑在生产同款数据库上**：PostgreSQL 的行锁死锁（如并行子 Agent 同会话 `SELECT ... FOR UPDATE`）在 SQLite 上测不出来。

### 4. 数据量与扇出上限

- [ ] **大对象流式处理**：上传边读边算哈希落单个缓冲文件或让客户端拿预签名 URL 直传对象存储，避免内存中拼接 `bytes` 造成 2–3 倍内存尖峰。
- [ ] **外层优先拦大小**：Ingress/Nginx（`client_max_body_size`）先挡一层，应用内再按类型校验上限与 MIME。
- [ ] **选择器、分页与子 Agent 扇出全设上限**：大工具输出存引用按页回读；任何总量封顶或截断都必须向调用方显式提示。

### 5. 空转与请求放大

- [ ] **没人用的时候系统必须是安静的**：高频定时任务（`<60s`）先用只读 `EXISTS` 探一下再开认领事务，并强制 `ignore_result=True`（写单测锁定，防止无人读取的结果键塞满 Redis）。
- [ ] **无写入者的定时任务默认关闭**：由部署开关控制，避免全环境每 5 秒空跑。
- [ ] **推送 + 增量替代全量快照轮询**：事件通知内联增量（超限才退回全量重拉）；轻量状态接口从数 MB 首屏聚合接口拆出；轮询带 Page Visibility 暂停与指数退避；高频重复检查加短 TTL / single-flight 缓存。

### 6. 超时不等式与干净停止

将以下多层超时关系写成**合同测试**，避免配置修改导致外层比内层先超时：

```text
queue_visibility_timeout > stale_cleanup_threshold > task_hard_limit > task_soft_limit > sub_agent_budget > tool_or_sse_timeout > llm_client_timeout
```

- [ ] **消灭所有无超时客户端**：每个 LLM SDK、HTTP 客户端、共享 Redis socket 都必须显式拆分连接/读/写/总超时。
- [ ] **绝不用宽泛 `except Exception` 吞掉 `SoftTimeLimitExceeded`**：必须单独捕获、落盘清理状态并重新抛出。
- [ ] **截止时间向下传递与协作式取消**：串行子 Agent 批次按任务数分摊父任务总预算；取消信号必须传播到子进程与远端工具。
- [ ] **用心跳 + 租约替代单纯“开始时间”清理僵尸任务**，覆盖内联请求、隐式结束工作流和孤儿子执行。

### 7. Agent 循环与 LLM 成本控制

- [ ] **多维度硬上限**：最大轮次、工具调用数、Token 与墙钟先到先收尾，收尾时引导模型基于已有信息给结论，而不是硬杀。
- [ ] **循环检测必须能终止而非只打警告**：按 `(tool_name, normalized_args_hash)` 追踪重复调用/连续失败；工具返回合法空结果时附加引导提示，防止空转几十轮。
- [ ] **清晰的模型交互契约**：对话历史用可读工具名而非内部 UUID；数字参数校验前做安全类型转换；校验失败返回可照改的错误信息（期望值 vs 实际值）。
- [ ] **按模型窗口推导上下文预算 + 工具结果三级降级**：保护最近的工具结果，窗口受限时按“全文 → 摘要 → 可回读引用”降级，避免直接丢弃导致模型反复重调振荡。
- [ ] **Prompt Caching 前缀稳定 + 按需暴露技能/工具**：固定前缀在前、动态内容在后；无可用技能时不暴露加载工具；同源告警风暴按指纹去重后再派单。

### 8. CPU、ReDoS 与资源回收

- [ ] **线性正则 + 输入长度封顶**：脱敏/解析正则禁止嵌套量词与重叠分支（Python 3.11+ 可用原子组 `(?>...)` 或使用 RE2），入口先截断超长不可信文本。
- [ ] **进程级客户端复用与上下文管理器**：HTTP / LLM / 向量库客户端随应用 lifespan 复用，所有 Session 与句柄一律 `with`/`async with`；测试中把 `ResourceWarning` 设为错误。
- [ ] **标准事件循环与有界 worker**：用 `asyncio.run()` 替代手写新建/关闭循环；配置 Celery `worker_max_tasks_per_child` / `worker_max_memory_per_child`；保留 `py-spy` 与 OpenTelemetry 排障能力。

## 2. 后端交付前五条硬规矩

1. **把隐含假设写下来**：列表最大行数、单会话最大事件数、最长任务耗时、并发人数、进程数——写进测试或注释，过期时立刻可见。
2. **给 Agent 尾部（P99）数据**：构造 10 万行资产、千事件会话的尾部数据集，锁与事务测试跑在生产同款数据库上。
3. **把跨层乘积集中在一处算**：一张连接池总账合同测试、一组超时不等式合同测试，让 CI 自动重算。
4. **第二次出现就写成门禁**：查询预算测试、高频任务 `ignore_result` 测试、`async def` 同步 `Session` AST 检查、连接池合同测试。
5. **留给后续的当场开 Issue，并检查空闲集成环境任务统计**：写在 commit 里的待办下一轮会话看不到；发版前看一眼**没人用时**集成环境的任务/SQL/Redis 统计——如果没人用时都在忙，有人用时只会崩得更快。
