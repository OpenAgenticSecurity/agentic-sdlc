# 前端 Vibe Coding 审查排雷清单（454 个真实问题实证）

**状态**: accepted baseline
**更新日期**: 2026-11-20
**English**: [frontend-vibe-coding-review.md](frontend-vibe-coding-review.md)
**实证来源**: [《Vibe Coding 的前端生死体验》](https://fz.cool/vibe-coding-issues-in-frontend/)（~10 万行 React/TS 前端 454 个去重问题；321 个可判断成因；216 个可判断发现渠道）

> **残酷现实**：后端出错会给你 HTTP 500 和堆栈；前端出错往往给你一个**看起来很正常的页面**。单测、TypeScript 与 CI 自己发现的问题仅占 **7%**（且多数靠浏览器 QA Agent）；**35%** 是人用的时候撞上的，**31%** 靠深度审计挖出来。

---

## 1. 前端验收“四连问”

`tsc`、单测和绿灯 CI 大多只能回答**第 1 问**；第 2–4 问必须在真实浏览器里沿用户路径走一遍：

1. **渲染出来了吗？**（组件能挂起不白屏）
2. **用户点得到吗？**（入口、路由守卫、权限、开关全部一致）
3. **显示的东西对吗？**（字段名、实时状态、真实错误、权威数据源）
4. **量大了以后还扛得住吗？**（长消息/宽表格、千行列表、慢网络、取消、重连、窄侧栏）

## 2. 454 个前端问题的实证归因（前四类占 84%）

| 成因类别 | 占比（分母 321） | 高发对应表现 |
|---|---|---|
| **1. 两边各自没错，中间那条边没人断言** | **39%** | 95% 的契约漂移、77% 的入口/权限不一致、45% 的状态时序 Bug |
| **2. 只在短 Demo / 小数据 / 单会话下成立** | **18%** | 45% 的状态时序 Bug、流式平方级重算、静默截断、无节制轮询 |
| **3. 就近照抄，没继承共享结构** | **16%** | 70% 的重复代码、55% 的布局缺陷、调用点反复打补丁 |
| **4. 用合理值兜底，不肯说“不知道”** | **11%** | 55% 的看起来合理的假值（`?? 0`、`|| []`、假 Fixture、吞错） |
| **5. 门禁或测试本身失效** | **4%** | 86% 的门禁失效（收集 0 测试返回 0、缺依赖 skip 返回 0、仅 advisory 不拦合并） |

## 3. 分区 PR 审查清单

### A. 看起来合理的假值（75 例 / 17%）

- [ ] **逐处审视 `?? 0`、`|| []`、`?? 'agent'` 与只有 `console.error` 的 `catch`**：读不到就老实显示“未知”或错误态，绝不编造像样的默认值。
- [ ] **明确拆分三种状态**：“加载中”“加载失败”“确实为空”绝不共用一个空数组 `[]`（防止加载中误把正常工具标成已停用/孤儿）。
- [ ] **一个展示语义只留一个权威字段**：禁止不同页面各写互相矛盾的兜底链（例如同一消息在一个页面回退成 `user`，另一个页面回退成 `agent`）。
- [ ] **禁止静默吞掉写操作失败**：删除/发送失败时必须保留用户输入或弹窗并明确报错，不无条件关闭确认框或删除刚输入的消息。
- [ ] **禁止静默截断关键信息**：任何长度截断或条数上限（180 字符预览、4000 字符报告、前 100 条会话）必须提示用户并提供展开/分页，绝不腰斩 JWT 或 PoC。
- [ ] **清理演示 Fixture 与假动画**：模拟数据必须带显式标记并在上线前扫描清理，不让写死的假模型或假状态留在主干。

### B. 前后端中间那条边（入口权限 44 例 + 契约漂移 43 例）

- [ ] **功能关闭三层联动测试**：当 feature flag 关闭时，一条测试同时管住三层——界面入口不可见、直接敲 URL 进不去、后端接口返回 `403`/`404`。
- [ ] **前端测试数据对齐后端真实 Schema**：避免手写 mock 顺着前端想象掩盖 `createdBy` vs `created_by` 这类字段漂移。
- [ ] **新接口与新开关两端核对**：后端新上线面向用户的接口，确认前端调用点；管理后台新加配置开关，确认运行时读取点（杜绝死开关）。
- [ ] **单条坏数据隔离**：单个节点或记录缺字段（如流程图节点缺 `position`）只能降级单张卡片，绝不拖垮整页。
- [ ] **防止截断表单反向删数据**：环境上限截断后的列表初始化表单时，保存绝不能把未加载的后端记录永久删掉。

### C. 脱离主线的状态与时序（94 例 / 21%）

- [ ] **一份数据只留一个状态源**：禁止同一批消息既存在查询缓存里又存在本地 Map 里靠多个 ref 打补丁同步。
- [ ] **登出 / 过期 / 切换身份必须清缓存**：防止上一个身份的数据串台残留。
- [ ] **测遍直线之外的所有岔路**：在真实浏览器里完整跑通切会话、停止/取消、停止后刷新、断网与用户主动停止的区分、重连、HITL 等待与恢复、乐观更新去重。
- [ ] **非幂等 POST 禁止自动重试**（除非具备显式幂等键）。
- [ ] **“一周三修”熔断**：同一个组件一周内修了三次以上，立刻停止修补表象，从状态机模型重新设计。

### D. 就近照抄与结构化约束（重复 28 + 布局 61 + 共享请求层 18）

- [ ] **同一根因第二次出现必须下沉到共享层**：绝不把“绕开共享 HTTP 客户端默认 `Content-Type: application/json` 破坏 `FormData`”的补丁与注释复制到第 2、3、5 个上传调用点。
- [ ] **绝不 mock 正在出问题的那一层**：上传/`FormData`/鉴权头/尾斜杠 307 重定向测试至少有一条真实走完客户端序列化。
- [ ] **把规矩做进代码结构，不靠文档祈祷**（文档里的规矩撑不过五次上下文压缩）：
  - 用统一骨架（`DetailHeader` + 唯一 `DetailBody` 主滚动流）禁止子面板私自套多层 `overflowY: 'auto'` 俄罗斯套娃滚动条；
  - 嵌套侧栏/双栏用 `@container` 容器查询而非全局视口媒体查询；
  - 封装单行控件（如 `AppTabs`）并用 Lint 禁掉裸组件导入，把正向结构断言挂在页面注册表而非逐文件登记。

### E. 规模退化与门禁自检（规模 23 + 门禁失效 14）

- [ ] **流式 Markdown 与宽表格**：按块边界冻结已定型前缀只解析一次，仅重算尾部（防每 token 平方级重算）；宽表格外层必须包横向滚动容器，不顶爆父级 Flex 布局。
- [ ] **虚拟列表稳定性**：始终配置基于稳定消息 ID 的 `computeItemKey`，绝不按数组位置索引。
- [ ] **轮询纪律**：遵循 Page Visibility（后台标签页暂停）、加指数退避，并把轻量状态接口与数 MB 首屏聚合接口拆开。
- [ ] **准备 P99 “又大又脏”的测试集**：长 Markdown 多列表格、数千行列表、跨 5 个数量级的十余个中文长标签图表、4K 屏与弱网回放。
- [ ] **每道门既要证明会红，也要证明红了拦得住**：
  - 故意植入一条违规确认门禁会变红；
  - `0 tests collected` 与缺依赖 `skip` 必须返回**非零退出码**；
  - Lint 规则降级（`error`→`warn`）、新增行内 `eslint-disable`、放宽打包体积预算必须单开 PR 并标注 owner 与到期日；
  - 在分支/Ruleset 保护中设为 **required status check**。

## 4. 前端交付前自查八问

1. **这次证明了哪一层？** 是仅渲染出来，还是点得到、全对、量大了也扛得住？
2. **验收是在哪里做的？** 仅终端单测全绿，还是在浏览器沿真实路径完整走过一遍？
3. **功能关掉时会怎样？** 界面入口、路由守卫、公共开关接口与后端拦截四处是否一致？
4. **读取失败时显示什么？** 老实显示“未知/错误”，还是用 `?? 0`、`|| []` 悄悄编了假值？长文本是否可展开且单一权威字段？
5. **非正常路径跑过没有？** 切会话、断网重连、用户取消、单条脏数据是否真测过？
6. **量大了排版会不会炸？** 宽表格有无横向滚动隔离？窄侧栏有无多层嵌套滚动条？
7. **这个 Bug 是第几次出现？** 第二次出现时是补在调用点还是下沉到了共享层？
8. **门禁真的能拦住人吗？** 是否为 required status check？有没有用反例确认缺依赖时不会 skip 返回 0？
